## Изменения

Выгрузка расширения конфигурации из хранилища теперь даёт файл, который
Конфигуратор открывает и сравнивает.

Проверено на двух хранилищах:

- малое расширение (4 объекта) — открылось, дерево метаданных разобралось,
  сравнение с эталоном прошло;
- большое расширение (224 объекта) — открылось, дерево разобралось.

### Формат `configinfo` расширения

- поле `{2,<GUID>,}` остаётся пустым: платформа проверяет его как подпись
  конфигурации и отвергает файл на любом непустом значении (проверено на
  трёх вариантах — полная сумма, короткая сумма, произвольные данные того же
  размера);
- GUID расширения берётся из заголовочной записи снимка версии
  `{6,<GUID снимка>,<GUID хранилища>,<GUID расширения>,...}`: в таблицах `.1CD`
  он не хранится, а поиск по телам даёт идентификатор объекта, не расширения;
- версия формата зависит от хранилища (у крупных — `1`), а не является
  константой `80327`;
- суммы объектов и версий — SHA1 тела в base64 (28 символов, ASCII).

### Контейнер

- `storage_ver` в заголовке растёт с каждым добавленным файлом: это число
  файлов контейнера, по нему читается таблица блоков. Прежний код увеличивал
  поле один раз за всё сохранение, из-за чего заголовок был неверным.

### Совместимость

- сборка под Boost 1.8x и новее: `get_digest` принимает `unsigned char[20]`,
  в более старых версиях — `unsigned int[5]`; перегрузка выбирается по
  фактической сигнатуре, дайджест получается одинаковым.
